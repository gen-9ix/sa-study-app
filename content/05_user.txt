@CARD user.id | UID、GID 與 Supplementary Groups
A> Kernel 不認名字只認號碼：alice 只是暱稱，系統裡真正的身分證號是 UID 1001。UID 0 是「萬能鑰匙」，不管叫什麼名字，只要號碼是 0 就是超級使用者。
B> 檔案擁有者與 process credentials 用的是**數字 ID**
B> 每個帳號有一個 **primary group**，並可屬於多個 **supplementary groups**
B> **UID 0 = superuser**，不論 login name 是什麼
B> 不要把 UID 0 給其他一般帳號
X> $ id alice
X> uid=1001(alice) gid=1001(alice) groups=1001(alice),2000(lab)

=T

@CARD user.types | 帳號類型
A> 一般使用者是「員工」、service/system user 是「每台機器各配一個的專屬機器人」（權限最小、不能登入）、directory user 是「總公司人事系統管理的員工」（LDAP 等）。
B> **Regular user**：真人、互動式登入，有自己的身分與家目錄
B> **Service / system user**：跑一個 daemon，權限受限、登入受限 → 每個服務用專屬身分
B> **Directory user**：集中管理，透過 **NSS** / 目錄服務解析
B> daemon、bin、sys、nobody 等歷史名稱在不同平台角色不同
?mc 為一個新的 web 服務設定執行身分，最佳做法是？
+ 建立專屬的 system user，限制其登入與權限
- 直接用 root 執行，避免權限不足造成錯誤
- 用 nobody 跑所有服務，統一管理比較方便
- 用管理員自己的帳號執行，出問題時好追查
E> 每個服務專屬身分，最小權限。
?mt 配對帳號類型：
> Regular user :: 真人使用，可互動登入，有家目錄
> Service user :: 專門跑某個 daemon，權限與登入都受限
> Directory user :: 由集中式目錄服務管理，透過 NSS 解析
E> 每個服務用自己的專屬身分，被攻破時影響範圍才小。

@CARD user.shadow | Shadow 密碼與雜湊格式
A> 為什麼要 shadow？/etc/passwd 必須讓每個人都能讀（程式要把 UID 轉成名字），如果雜湊放在那裡，任何人都能拿回家慢慢暴力破解。所以把雜湊搬進只有 root 能讀的「保險箱」/etc/shadow。$6$ 這種前綴是「保險箱的鎖型號」。
B> Debian：**/etc/shadow**；FreeBSD：**/etc/master.passwd** 與資料庫（pwd.db / spwd.db）
B> 存的是 **salted password hash**，不是可還原的加密密碼
B> 用帳號工具（passwd、adduser、usermod、vipw）保持紀錄一致
B> 雜湊前綴：**$1$ = MD5**（舊、不安全）、**$2…$ = bcrypt**、**$5$ = SHA-256**、**$6$ = SHA-512 crypt**、**$y$ = yescrypt**（現代 Debian）
B> shadow 欄位：1-2 名稱與 hash、3-6 上次修改日 / 最短 / 最長 / 警告天數、7-9 inactive 天數 / 帳號到期日 / 保留
B> **密碼到期**要求改密碼；**帳號到期**會依政策阻擋存取
?sa A. 使用者可以屬於多個 group，在 /etc/passwd 中設定 group 與寫在 /etc/group 有何差異？ B. 何謂 shadow passwd？為何現在大多數系統都採用？ C. 如何從 /etc/master.passwd（或 /etc/shadow）判斷使用者的密碼使用哪種 hash function？（例：root:$6$gW9y$NtFj3pni:0:0:root:/root:/bin/sh）
S> 2023 期末 Q12
R> A. /etc/passwd 的 GID 欄位是使用者的 primary group（只能有一個，建立檔案時預設的群組）；/etc/group 每行最後的成員清單列的是 supplementary（附加）群組成員，一個使用者可以出現在多個群組中。
R> B. shadow passwd 是把密碼 hash（與密碼期限資訊）從所有人都可讀的 /etc/passwd 移到只有 root 可讀的 /etc/shadow（FreeBSD 為 /etc/master.passwd），/etc/passwd 的密碼欄只留 x 或 *。因為 /etc/passwd 必須公開讓程式查 UID↔名稱，若 hash 放在裡面任何人都能拿去離線暴力破解，所以分開存放更安全。
R> C. 看密碼欄位 $id$salt$hash 的前綴 id：$1$ 是 MD5、$2a$/$2b$ 是 bcrypt、$5$ 是 SHA-256、$6$ 是 SHA-512、$y$ 是 yescrypt。例子中 $6$ 表示 SHA-512（salt 為 gW9y）。
P> A. passwd 的 GID 是 primary group；/etc/group 列 supplementary 成員
P> B. hash 移到 root 才能讀的檔案，防止離線破解
P> C. 由 $id$ 前綴判斷，$6$ = SHA-512
?mt 配對 hash 前綴：
> $1$ :: MD5（舊式，不適合新密碼）
> $6$ :: SHA-512 crypt
> $y$ :: yescrypt
> $2b$ :: bcrypt
E> 格式 $id$salt$hash。
?tf /etc/shadow 中存的是用 root 金鑰加密、可以解密還原的密碼。
=F
E> 是加鹽的單向 hash，無法還原。
?cmd 查看 alice 的密碼與帳號期限資訊（不顯示 hash）：
= chage -l alice
E> chage 管理 aging。

@CARD user.gecos | GECOS 與 Login Shell
A> chfn 改「名片」（finger 資訊），chsh 改「預設搭乘的交通工具」（login shell）。換 shell 前先確認它在 /etc/shells 這張「合法交通工具清單」上。
B> **chfn**：修改 GECOS（全名、聯絡資訊）
B> **chsh -s /bin/sh**：修改 login shell；先查 **/etc/shells**
B> login shell 是**設定值**，不一定是目前正在執行的 shell
B> **nologin** 阻擋一般 shell 登入，但不代表擋住所有認證路徑（如 SFTP 另有設定）
?cmd 把自己的 login shell 改成 /bin/sh：
= chsh -s /bin/sh
E> 先 cat /etc/shells 確認路徑合法。
?sa a. 下列指令已把 shell 從 tcsh 改成 sh，但印 $SHELL 仍是 tcsh，為什麼？ b. 要怎麼知道目前的 shell 是什麼？
QX> $ echo $SHELL
QX> /bin/tcsh
QX> $ sh
QX> $ echo $SHELL
QX> /bin/tcsh
S> 2023 期中 Q11
R> a. 執行 sh 只是在 tcsh 底下開了一個 sh 子行程，並沒有改變帳號設定。$SHELL 是登入時根據 /etc/passwd 設定的 login shell 所設的環境變數，sh 從父行程繼承了這個環境變數，且 sh 不會去改它，所以仍是 /bin/tcsh。
R> b. 用 echo $0（顯示目前 shell 程式名稱），或 ps -p $$（查看目前 shell PID 對應的程式），也可用 ps 看 process 樹。
P> a. $SHELL 是 login shell 的環境變數，由父行程繼承，不會因執行 sh 而改變
P> b. echo $0 或 ps -p $$
?cmd 顯示目前正在執行的 shell 是哪個程式（用 ps 與 $$）：
= ps -p $$
= ps -p $$ -o comm
= ps -o comm -p $$
E> $$ 是目前 shell 的 PID。

@CARD user.group | /etc/group 與群組成員
A> /etc/group 的最後一欄是「社團的附加成員名單」；你的 primary group 寫在 /etc/passwd，所以不一定會出現在這份名單上。加入新社團後，已經在場的你（現有 process）不會自動拿到新社員證，要重新登入。

B> **既有的 process 保留舊的 credentials** → 在**新的 login session** 測試群組
B> FreeBSD **wheel** 群組與預設 su 政策有關；Linux 的 su/sudo 規則由 PAM 與 sudoers 決定
?tf 把 alice 加入 docker 群組後，alice 目前已開著的 shell 立刻就有 docker 群組權限。
=F
E> 現有 process 保留舊 credentials，要重新登入（或 newgrp）。
?fill /etc/group 一行的格式是 name:password-marker:＿＿:members
= gid
= GID
E> 例如 lab:x:2000:alice,bob。

@CARD user.nsspam | NSS 與 PAM
A> NSS 是「查名冊的人」（這個帳號是誰？從檔案、LDAP 哪裡查）；PAM 是「門口保全」，分好幾關：auth（你是本人嗎）、account（帳號能用嗎、過期了嗎）、session（登入後幫你準備環境，例如套用 limits）。
B> **NSS**：解析使用者與群組 → **/etc/nsswitch.conf**
B> **PAM auth / account**：驗證身分與帳號政策 → **/etc/pam.d/**
B> **PAM session**：設定登入 session（服務專屬的 PAM stack）
B> **getent** 顯示透過 NSS 解析到的身分
B> 有 passwd 紀錄 ≠ 所有登入方式都允許
?mt 配對：
> NSS :: 查詢使用者 / 群組（/etc/nsswitch.conf）
> PAM auth :: 驗證使用者身分（密碼等）
> PAM account :: 帳號限制（到期、是否允許）
> PAM session :: 設定登入 session（如 limits）
E> 身分查詢、認證、帳號限制、session 設定是不同工作。
?mc /etc/passwd 中有 alice 這一行，但她用 SSH 登入被拒。下列哪個說法合理？
+ 有 passwd 紀錄只代表帳號存在；能不能登入還要看 PAM 政策與各服務的設定
- passwd 有紀錄就代表可以用任何方式登入，一定是 SSH 本身壞了
- passwd 中的密碼欄是 x，代表帳號已被鎖住，任何方式都無法登入
- 代表她的 UID 是 0，而 sshd 預設禁止 root 登入，要改 PermitRootLogin
E> NSS 負責「查得到」，PAM 負責「准不准」。
?fill 決定「使用者與群組資料要去哪裡查」的設定檔是 /etc/＿＿
= nsswitch.conf
E> 例如 passwd: files systemd 表示先查本機檔案，再查 systemd 提供的動態使用者。

@CARD user.limits | 資源限制 limits
A> soft limit 是「平常的額度」，使用者可以自己往上調，但不能超過 hard limit 這個「天花板」。PAM 的 limits 只管「登入的人」，systemd 服務要在 unit 裡另外設 LimitNOFILE=。
B> 設定於 **/etc/security/limits.d/**（如 @lab soft nofile 1024、@lab hard nofile 4096）
B> **pam_limits** 在 PAM session stack 包含它時套用
B> **soft** 可被提高到 **hard** 為止
B> 查看：**ulimit -Sn**（soft）、**ulimit -Hn**（hard）開檔數
B> systemd 服務：用 **LimitNOFILE=** 等 unit 資源設定；PAM 限制**不會**自動套用到服務
?tf 在 /etc/security/limits.d/ 設定的限制，也會自動套用到 systemd 啟動的 service。
=F
E> 服務不經 PAM login session，要在 unit 用 LimitNOFILE= 等設定。
?cmd 查看目前 shell 可開啟檔案數的 hard limit：
= ulimit -Hn
= ulimit -n -H
E> -H hard、-S soft、-n nofile。

@CARD user.create | 建立帳號：adduser / useradd
A> adduser 是 Debian 的「親切櫃台」，會互動式問你問題、自動建家目錄與 skeleton；useradd 是「後台表單」，參數要自己填清楚（例如 -m 才建家目錄）。兩條路選一條就好，不是兩個步驟。
B> 流程：選唯一名稱與群組 → 用工具建立紀錄、家目錄、skeleton → 設定初始認證 → 套用配額、到期、權限政策 → **驗證**身分、家目錄擁有者、shell、實際登入
B> Debian：**adduser alice**（互動）、**addgroup lab**、**adduser alice lab**（加入附加群組）
B> 低階：**useradd -m -s /bin/bash alice** + **passwd alice**；預設由 /etc/default/useradd、/etc/login.defs 影響
B> 不要把每個新帳號都加進 sudo
?cmd 用 useradd 建立 alice，同時建立家目錄並指定 shell 為 /bin/bash：
= useradd -m -s /bin/bash alice
= useradd -s /bin/bash -m alice
E> -m 建家目錄、-s 指定 shell。
?cmd 在 Debian 上用 adduser 把既有使用者 alice 加入 lab 群組：
= adduser alice lab
E> adduser <user> <group>。
?tf useradd 和 adduser 是建立帳號的兩個必要步驟，要依序都執行。
=F
E> 擇一即可，是兩條不同的建立路徑。

@CARD user.home | 家目錄、skeleton、密碼與配額
A> /etc/skel 是「新生入學禮包」：建帳號時複製一份到新家目錄。之後改禮包，不會影響已經入學的學生。Quota 的 soft limit 是「超過會收到警告並有寬限期」，hard limit 是「絕對不能再多」；block 限制容量、inode 限制檔案數量。
B> **/etc/skel**：建立新使用者時複製到家目錄的範本；之後修改**不會**更新既有家目錄
B> /home/<user>：一般本機使用者家目錄；.profile、.bashrc 等啟動檔
B> 驗證家目錄擁有者、群組、權限；遞迴 chown 前先理解範圍
B> **passwd alice** 設密碼
B> 配額：需要檔案系統支援與設定；**edquota -u alice**、**quota -u alice**
B> **soft** 有寬限期；**hard** 直接阻擋；**block** 與 **inode** 限制不同資源
?mt 配對 quota 概念：
> soft limit :: 超過後有寬限期（grace period）
> hard limit :: 絕對上限，直接阻擋配置
> block limit :: 限制使用的容量
> inode limit :: 限制檔案（物件）數量
E> 兩組維度：soft/hard × block/inode。
?tf 修改 /etc/skel 中的 .bashrc，所有既有使用者的 .bashrc 都會跟著更新。
=F
E> skel 只在建立帳號時被複製。

@CARD user.lock | 鎖定密碼與撤銷存取
A> passwd -l 只是「把密碼這道門鎖起來」，但對方可能還有別的鑰匙：SSH key、已經登入的 session、排程工作、token… 撤銷存取要每一道門都檢查。
B> **passwd -l alice**：鎖定**密碼**認證；**passwd -S alice** 看狀態；**passwd -u** 解鎖
B> 鎖密碼**不會**自動撤銷 **SSH keys** 或終止**現有 session**
B> 要檢查：帳號到期、keys、tokens、目錄政策、cron 工作、active sessions
B> 用帳號工具，**不要**手動註解掉 passwd / shadow 的行
?mc 對 alice 執行 passwd -l alice 後，下列哪件事「仍然可能」發生？
+ alice 用已設定好的 SSH key 登入
- alice 用密碼登入
- alice 用 su - alice 輸入密碼切換
- 以上都不可能
E> 鎖密碼不影響公鑰認證，也不會踢掉現有 session。
?cmd 鎖定 alice 的密碼認證：
= passwd -l alice
= usermod -L alice
E> -l = lock。

@CARD user.remove | 帳號離職與刪除
A> 員工離職：先收回所有鑰匙（撤銷存取）、備份他的資料、盤點他負責的東西（cron、郵件、檔案），最後才把名字從名冊刪掉。刪了帳號，他留在各處的檔案還在，只是擁有者變成「一個沒人認領的號碼」，若這個號碼之後給新人，新人就會「繼承」那些檔案。
B> 盤點：擁有的檔案、mail、cron、keys、processes、外部憑證
B> 先**確認備份、撤銷存取**，再刪除本機紀錄
B> **deluser alice**：預設**保留家目錄**；**deluser --remove-home alice** 需核准
B> 低階：**userdel alice**（-r 刪家目錄）
B> 刪帳號**不會刪掉它所有檔案**；UID 重新使用前，要先處理以舊 UID 擁有的檔案
?mc 刪除帳號後，若該 UID 被分配給新使用者，最大的風險是？
+ 新使用者會擁有舊帳號遺留在系統各處的檔案
- 新使用者無法登入
- 新使用者登入時會看到舊使用者的密碼提示
- 新使用者的密碼會和舊使用者相同
E> 檔案以數字 UID 記錄擁有者。
?cmd 在 Debian 上刪除帳號 alice，並一併刪除其家目錄：
= deluser --remove-home alice
= userdel -r alice
E> deluser 預設保留家目錄。

@CARD user.root | Superuser 的權限與邊界
A> root 是「大樓萬能鑰匙」：檔案、process、裝置、系統設定都能動。平常用自己的名牌上班，需要時才短暫借用萬能鑰匙。

@CARD user.p_sudo | 實作：sudoers 安全修改與排錯
A> sudoers 寫錯一個字，可能整台機器都沒人能 sudo，所以一定要經過 visudo 這個「會先檢查文法的編輯器」。規則是由上往下讀、**最後一條符合的規則勝出**，這解釋了大部分「明明寫了 NOPASSWD 卻還是問密碼」的問題。
B> 編輯：**visudo**（主檔）、**visudo -f /etc/sudoers.d/judge**（附加檔）；只檢查：**visudo -c**
B> /etc/sudoers.d/ 內的檔名**不能有 . 或以 ~ 結尾**，否則會被略過；權限應為 0440
B> 範例：`judge ALL=(ALL:ALL) NOPASSWD: ALL`；群組前加 %：`%sudo ALL=(ALL:ALL) ALL`
B> **最後符合的規則生效**：使用者若同時在 sudo 群組，而 %sudo 那行排在你的 NOPASSWD 之後，就會又要密碼 → 把自己的規則放在後面（@includedir 在主檔最後，所以 sudoers.d 通常會贏）
B> 查某人最後到底有哪些權限：**sudo -l -U 使用者**
X> echo 'judge ALL=(ALL:ALL) NOPASSWD: ALL' | sudo tee /etc/sudoers.d/judge
X> sudo chmod 0440 /etc/sudoers.d/judge
X> sudo visudo -c
X> sudo -l -U judge
?cmd 檢查 sudoers 主檔與所有 include 檔案的語法是否正確：
= visudo -c
= sudo visudo -c
E> 用 tee 或 echo 直接寫入 sudoers.d 之後，一定要跑這行。

- 兩條中比較嚴格的那一條
