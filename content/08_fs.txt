@CARD fs.lsl | 讀懂 ls -l
A> ls -l 的一行就是檔案的「身分證」：類型 + 權限、連結數、擁有者、群組、大小、修改時間、名字。
B> drwx--x--x 7 tsaimh dcs 1024 Sep 22 17:25 public_html
B> **d**：檔案類型；**rwx--x--x**：存取權限（user / group / other）
B> **7**：連結數（link count）
B> **tsaimh**：擁有者；**dcs**：群組
B> **1024**：大小；**Sep 22 17:25**：最後修改時間；最後是檔名
?mc 在 -rw-r--r-- 2 amy staff 512 Oct 1 a.txt 中，2 代表？
+ hard link 數
- 檔案版本
- 擁有者的 UID
- 區塊數
E> hard link 數（指向同一個 inode 的名稱數）兩個檔名共用一個 inode。
?mt 配對 ls -l 輸出「drwx--x--x 7 tsaimh dcs 1024 Sep 22 17:25 public_html」的各欄位：
> d :: 檔案類型（目錄）
> 7 :: 連結數
> tsaimh :: 擁有者
> dcs :: 群組
> 1024 :: 大小
E> 權限字串之後依序是：連結數、擁有者、群組、大小、修改時間、檔名。
?mc 權限 rwx--x--x 的目錄，「其他人」可以做什麼？
+ 能進入，但不能列出內容
- 可以列出內容但不能進入
- 什麼都不能做
- 可以在裡面建立檔案
E> 可以 cd 進去並存取已知名稱的檔案，但不能 ls 列出內容。只有 x 沒有 r：能進入、不能列出。

@CARD fs.arch | 檔案系統架構與四大元件
A> 應用程式不直接碰硬碟，而是透過 system call 請 kernel 幫忙；kernel 再透過 VFS（統一的櫃台）轉給各種檔案系統（ext4、msdos、proc…）和驅動程式。
B> Application ↔（system call）↔ Kernel ↔（driver）↔ Hardware
B> Kernel 中：**Virtual File System (VFS)** → 各檔案系統（ext2、msdos、proc…）→ buffer cache → device drivers
B> 檔案系統四大元件：**Namespace**（命名與階層，如目錄）、**API**（操作的 system calls）、**Security model**（權限）、**Implementation**（對應到實體磁碟的程式碼）
B> cp file1 file2 的 system call 序列：open 輸入 → create 輸出 → 迴圈 read / write 直到 EOF → close
B> 檔案系統裡不只有檔案：目錄、裝置檔、process 資訊（/proc）、IPC、shared memory → 統一用 open、read、write、close、seek、ioctl、fcntl 存取
?mt 配對檔案系統四大元件：
> Namespace :: 命名與階層結構（目錄）
> API :: 操作節點的 system calls
> Security model :: 保護、隱藏與分享（權限）
> Implementation :: 把邏輯模型對應到磁碟的程式碼
E> 這四個是 filesystem 的基本目的。
?ord cp file1 file2 的 system call 順序：
> open 輸入檔
> create 輸出檔
> 迴圈 read / write 直到 EOF
> close
E> 投影片的 cp 範例。
?mc Kernel 中讓不同檔案系統（ext4、proc、msdos…）都能用同一組 system call 存取的那一層叫做？
+ Virtual File System（VFS）
- buffer cache（區塊快取）
- device driver（裝置驅動程式）
- shell 的檔案操作抽象層
E> VFS 提供統一介面，底下再接各檔案系統的實作。

@CARD fs.hier | 目錄階層 hier(7)

B> **/bin & /sbin**：單人/多人模式都必需的使用者工具與系統程式

B> **/usr/local**：本地安裝的執行檔、函式庫等；**/usr/local/etc** 模仿 /etc
B> **/etc**：系統設定檔與腳本
B> **/dev**：裝置檔；**/proc**：執行中 process 的映像

B> **/tmp**：重開機後不保證保留；另有 /var/tmp
B> **/mnt**：暫時掛載點；/lib 共享函式庫；/libexec 關鍵系統工具

@CARD fs.mount | mount 與 umount
A> mount 是「把一個新的儲物櫃接到大樓的某個門口」：之後走進那個門（mount point）看到的就是新櫃子的內容，原本門後的東西暫時被擋住看不到（但沒消失）。有人正在櫃子裡（cd 在裡面或開著檔案）時，你沒辦法把櫃子拆走（busy）。
B> **mount**：把新檔案系統的 root 對應到現有檔案樹的掛載點；例 mount /dev/ad2s1e /home2
B> 掛載點**原本的內容會暫時看不到**
B> 可掛載：磁碟分割、網路檔案伺服器、記憶體磁碟、kernel 元件（/proc）
B> **umount { node | device }**；busy 時（有人 cwd 在裡面或有開啟的檔案）會失敗
B> **umount -f** 強制；用 **lsof**（Linux / FreeBSD）或 **fstat**（FreeBSD）找出誰在用
?mc umount /home 失敗並顯示 target is busy，最可能原因是？
+ 有 process 的工作目錄在 /home 裡，或開著 /home 下的檔案
- /home 沒有寫入權限，所以無法把 dirty page 寫回後卸載
- /etc/fstab 中沒有 /home 這一行，所以 umount 找不到它
- 磁碟已滿，journal 無法寫入卸載前的最後一筆紀錄
E> 用 lsof / fuser / fstat 找出是誰。
?tf 把新的檔案系統 mount 到一個非空目錄上，原本目錄內的檔案會被刪除。
=F
E> 只是暫時被遮住，umount 之後就會再出現。
?cmd 列出開啟中的檔案以找出是誰讓 /home 忙碌（Linux）：
= lsof /home
= lsof +D /home
= fuser -m /home
= fuser -vm /home
E> lsof = list open files。

@CARD fs.fstab | /etc/fstab 與 UUID
A> /etc/fstab 是「開機時的自動掛載清單」。用 /dev/sdb 指定磁碟像用「排隊號碼」叫人，今天第二個到的人明天可能變第三個；用 UUID 像用「身分證號」叫人，不管排第幾都找得到同一個。
B> 開機時自動檢查並掛載：**Device  Mountpoint  FStype  Options  Dump  Pass#**
B> Pass：fsck 順序（root 為 1、其他 2、不檢查 0）；Dump：是否給 dump 備份
B> 建議用 **UUID=…**（或 LABEL=）指定裝置，查詢用 **blkid** / lsblk -f
X> # Device      Mountpoint FStype Options Dump Pass#
X> /dev/ad0s1a  /          ufs    rw      1    1
X> /dev/ad0s1b  none       swap   sw      0    0
X> UUID=0ed6…   /home/ray  btrfs  subvol=/home/@ray 0 0
?sa 在 /etc/fstab 中，我們偏向使用 UUID 來指定硬碟，而非使用 /dev/sdX，請解釋原因。
S> 2025 期末 Q4
R> /dev/sdX 是 kernel 依「偵測到的順序」動態分配的名稱，並不固定：新增或移除硬碟、插入 USB 碟、更換插槽 / 控制器、驅動載入順序不同、甚至每次開機的偵測時序差異，都可能讓原本的 /dev/sdb 變成 /dev/sdc。若 fstab 寫 /dev/sdX，就可能掛錯磁碟（資料寫到錯的地方）或找不到裝置導致開機失敗（進入 emergency mode）。
R> UUID 是建立檔案系統（mkfs）時產生、寫在檔案系統 metadata 中的唯一識別碼，不隨裝置名稱或順序改變，所以能穩定地找到同一個檔案系統。可用 blkid 或 lsblk -f 查詢。
P> /dev/sdX 依偵測順序分配，會因增減磁碟等原因改變
P> 可能掛錯或找不到而開機失敗
P> UUID 是檔案系統唯一且固定的識別碼
?cmd 查詢各個區塊裝置的檔案系統 UUID：
= blkid
= lsblk -f
= lsblk -o NAME,UUID
E> blkid 或 lsblk -f。
?mc fstab 第 6 欄（pass）為 0 代表？
+ 開機時不執行 fsck 檢查
- 開機時第一個執行 fsck 檢查
- 開機時不掛載這個裝置
- 以唯讀方式掛載這個裝置
E> root 通常 1，其他 2，不檢查 0。

@CARD fs.ipc | Socket、Pipe 與 Named Pipe
A> pipe 是只有親戚（parent/child）才拿得到的輸送帶；named pipe（FIFO）把輸送帶掛上門牌，誰都能從門牌找到它；UNIX domain socket 是本機內的電話專線，用檔案路徑而不是 port 號碼來撥號。
B> **UNIX domain socket**：socket() 建立，只在本機，透過**檔案系統物件**而非網路 port 存取
B> **Pipe**：兩個 process 間 FIFO 溝通（通常 parent fork 前建立，fd[0] 讀、fd[1] 寫）
B> **Named pipe**：**mkfifo [-m mode] name**；不相關的 process 也能用
X> $ mkfifo pipe
X> $ du >> pipe        # 一個 process 寫
X> $ sort -n pipe      # 另一個 process 讀
?cmd 建立一個名為 mypipe 的 named pipe：
= mkfifo mypipe
E> ls -l 會看到類型 p。
?mc UNIX domain socket 和 TCP socket 的主要差異？
+ UNIX socket 只在本機，以檔案系統路徑定址，而非 IP:port
- UNIX socket 只能單向傳輸，要雙向通訊必須開兩個 socket
- UNIX socket 需要網路卡，只是封包不會離開這台機器
- UNIX socket 比 TCP 慢，因為每次傳輸都要寫入磁碟
E> 例：/run/docker.sock。

@CARD fs.inode | inode 與分割區結構
A> inode 是檔案的「戶口名簿」：記錄擁有者、權限、時間戳記、大小、資料放在哪些區塊（直接、單/雙/三層間接指標），但**沒有檔名**。檔名寫在目錄裡：目錄只是一張「檔名 → inode 號碼」的對照表。
B> **inode** 記錄：mode、owners、timestamps、size、link count、資料區塊指標（**direct、single / double / triple indirect**）
B> **ls -i** 看 inode 號碼
B> 分割區四部分：**boot block**（開機程式）、**super block**（檔案系統狀態：大小、block size、root 目錄 inode…）、**inode list**、**data blocks**
B> 使用者用檔名思考；**Unix 用 inode 思考**
B> **目錄**的內容 = 一筆筆 (inode 號碼, 檔名)；包含 . 與 ..
?tf 檔案的名稱存在它的 inode 裡。
=F
E> 檔名存在目錄的資料區塊（檔名 → inode 號碼）；inode 不含檔名，所以才能有多個 hard link。
?mt 配對分割區元件：
> Boot block :: 載入作業系統的開機程式
> Super block :: 檔案系統整體狀態（大小、block size…）
> Inode list :: 所有 inode 的陣列
> Data blocks :: 檔案的實際內容
E> UFS 經典結構。
?cmd 列出目前目錄檔案及其 inode 號碼：
= ls -i
= ls -li
= ls -il
E> -i 顯示 inode。

@CARD fs.link | Hard link vs Symbolic link
A> Hard link 是「同一個人多一個名字」：兩個名字指向同一份戶口（inode），刪掉一個名字，人還在，直到所有名字都刪光。Symbolic link 是「寫著地址的便條紙」：它記的是路徑，原本的人搬走（刪除）就變成死連結；如果有新的人搬進同一個地址，便條紙就指向新人。
B> **Hard link**：多個檔名指向**同一個 inode**；**必須在同一個檔案系統（partition）**；ln ori hard
B> **Symbolic link**：一個檔案，內容是**另一個路徑名**；ln -s ori soft；像 Windows 捷徑
B> 刪除原檔：hard link 仍可讀（inode link count 還 > 0）；symlink 變成 dangling（壞掉）
B> 再建立同名新檔：symlink **指向新檔**（因為它記的是路徑）；hard link 仍是**舊內容**
B> symlink 可跨檔案系統、可指向目錄；hard link 一般不能指向目錄
?sa 請問下列兩個 cat 指令的輸出為何？
QX> $ echo "start" > myfile
QX> $ ln -s myfile link1
QX> $ ln myfile link2
QX> $ rm myfile
QX> $ echo "end" > myfile
QX> $ cat link2
QX> $ cat link1
S> 2025 期末 Q19
R> cat link2 輸出 start；cat link1 輸出 end。
R> link2 是 hard link，和原本的 myfile 指向同一個 inode；rm myfile 只刪除了一個名稱，inode 仍被 link2 引用，所以內容 start 還在。之後 echo "end" > myfile 建立的是全新的 inode。
R> link1 是 symbolic link，只記錄路徑 "myfile"；cat 時會去解析這個路徑，找到的是新建的 myfile，所以輸出 end。
P> link2 → start（hard link 指向舊 inode）
P> link1 → end（symlink 依路徑找到新檔）
?sa 試說明 symbolic link 和 hard link 的差異。
S> 2023 期末 Q8
R> Hard link：在目錄中新增一個名稱指向「同一個 inode」，與原檔完全平等，inode 的 link count 加一；必須在同一個檔案系統內，通常不能對目錄建立；刪除其中一個名稱，資料仍在，直到 link count 歸零才真正釋放。
R> Symbolic link：是一個獨立的特殊檔案（有自己的 inode），內容存的是目標的路徑名稱；可以跨檔案系統、可以指向目錄；原檔刪除或搬移後就會失效（dangling），若同路徑出現新檔則會指向新檔。ls -l 中類型為 l。
P> hard link 共用同一個 inode；symlink 存路徑
P> hard link 不能跨檔案系統 / 目錄；symlink 可以
P> 原檔刪除：hard link 仍可用，symlink 失效
?mc 建立 hard link 時，下列哪個限制正確？
+ 原檔和連結必須在同一個檔案系統
- 原檔必須屬於建立連結的使用者
- 原檔必須是可執行檔
- 只有 root 能建立
E> 因為 inode 號碼只在同一個檔案系統內有意義。
?cmd 為 /etc/nginx/sites-available/site 建立名為 /etc/nginx/sites-enabled/site 的 symbolic link：
= ln -s /etc/nginx/sites-available/site /etc/nginx/sites-enabled/site
= ln -s /etc/nginx/sites-available/site /etc/nginx/sites-enabled/
= ln -s /etc/nginx/sites-available/site /etc/nginx/sites-enabled
E> ln -s 目標 連結名。

@CARD fs.mode | 權限 rwx 與 chmod
A> 九個權限位元分三組：擁有者（u）、群組（g）、其他人（o）；r=4、w=2、x=1 加起來就是一位數字。chmod 有兩種語法：符號法（u+x、go-w）像「微調」，數字法（755）像「整組重設」。
B> **rwx r-x r-x**：user / group / other
B> 數字：**r=4、w=2、x=1** → 755 = rwxr-xr-x、644 = rw-r--r--、600 = rw-------
B> 符號：chmod **u+x** test.sh、chmod **go-w** .tcshrc、chmod u+w,g-w hehe haha
B> 遞迴：chmod **-R** 755 public_html/
?fill rwxr-x--- 的數字表示是＿＿
= 750
E> rwx=7、r-x=5、---=0。
?fill 640 的權限字串是＿＿
= rw-r-----
E> 6=rw-、4=r--、0=---。
?cmd 移除 group 和 other 對 secret.txt 的所有權限（符號寫法）：
= chmod go-rwx secret.txt
= chmod go= secret.txt
= chmod g-rwx,o-rwx secret.txt
E> 或用數字 chmod 600（若 user 本來就是 rw）。

@CARD fs.dirperm | 目錄權限與「刪除檔案」
A> 目錄是一本「名冊」：r 是能讀名冊（ls 列出檔名）、w 是能在名冊上新增 / 劃掉名字（建立、刪除、改名）、x 是能「進入並通過」這個目錄（cd、存取裡面的檔案）。所以**能不能刪一個檔案，看的是目錄的 w+x，不是檔案本身的權限**。
B> 目錄 **r**：列出內容（ls）；**x**：進入 / 通過（cd、存取其中檔案）；**w**（需搭配 x）：建立、刪除、改名
B> 最小權限表：cd → 目錄 x；ls → 目錄 r；ls -s *.c → 目錄 rx；cat file → 檔案 r + 目錄 x；cat >> file → 檔案 w + 目錄 x；執行 binary → 檔案 x + 目錄 x；執行 script → 檔案 **rx** + 目錄 x；**rm file → 目錄 wx**（檔案本身不需要權限）
B> 只有 x 沒有 r：可以 cd 進去、可以存取「知道名字」的檔案，但無法 ls（HW2 的 private/hidden 就是這樣設計）
?mt 配對動作與「最少」需要的權限：
> cd /home/test :: 目錄 x
> ls /home/test :: 目錄 r
> rm /home/test/f :: 目錄 w 與 x
> 執行 shell script :: 檔案 r 與 x，目錄 x
> cat /home/test/f :: 檔案 r，目錄 x
E> script 要讀才能被直譯器執行，所以要 rx；binary 只要 x。
?tf 要刪除一個檔案，必須對該檔案本身有 w 權限。
=F
E> 刪除是修改「目錄」的內容，需要目錄的 w+x（加上 sticky 的額外限制）。
?mc 目錄權限為 --x（只有 x），使用者可以做什麼？
+ cd 進去並存取已知名稱的檔案，但無法 ls 列出內容
- 可以 ls 列出內容與檔案屬性，但無法 cd 進去或讀取
- 可以 ls 列出檔名，但無法讀取任何檔案的內容
- 什麼都不能做，對目錄來說 x 沒有任何意義
E> HW2 private/ 的「能 cd、不能 ls、能 get 知道名字的 treasure」就是這個原理。

@CARD fs.special | setuid、setgid、sticky bit
A> 三個特殊位元：setuid 是「借擁有者的身分做事」（passwd）；setgid 在目錄上是「在這裡出生的檔案，自動入籍這個群組」；sticky 在目錄上是「公共置物區，只准動自己的東西」（/tmp），只有檔案擁有者、目錄擁有者、root 能刪/改名。
B> **setuid（4000）**：在**檔案**上，執行時 EUID = 檔案擁有者；例 passwd、chsh、crontab；顯示為 user 的 **s**
B> **setgid（2000）**：在檔案上 EGID = 檔案群組；在**目錄**上，**新建的檔案繼承目錄的群組**；顯示為 group 的 **s**
B> **sticky（1000）**：在**目錄**上，除非你是**檔案擁有者、目錄擁有者或 root**，否則不能刪除或改名其中的檔案；顯示為 other 的 **t**（/tmp = 1777 drwxrwxrwt）
B> 大寫 S / T：對應的 x 位元沒開
X> 4755 -rwsr-xr-x    2755 -rwxr-sr-x
X> 2775 drwxrwsr-x    1777 drwxrwxrwt
?sa 請說明下列 /tmp 資料夾權限中的 t 所代表的意義與作用。
QX> drwxrwxrwt  38 root  wheel  42 Nov  4 22:20 /tmp
S> 2023 期末 Q11
R> t 是 sticky bit（數字 1000，/tmp 為 1777）。設在目錄上時，雖然所有人都有 rwx、都能在 /tmp 建立檔案，但只有「該檔案的擁有者」、「目錄的擁有者」或 root 才能刪除或重新命名其中的檔案。作用是讓 /tmp 這種公共可寫目錄中，使用者不能刪除或改名別人的檔案。t 為小寫代表 other 的 x 也有開。
P> t = sticky bit
P> 只有檔案擁有者 / 目錄擁有者 / root 可刪除或改名
P> 防止公共目錄中互刪檔案

= 2775

@CARD fs.umask | umask
A> umask 是「預設會被拿掉的權限」：檔案從 666、目錄從 777 出發，把 umask 有的位元「遮掉」。注意不是減法，是遮罩（AND NOT）：umask 033 時檔案是 644，不是 633。
B> shell built-in；決定**新建**檔案/目錄的預設權限
B> 新權限 = **full & ~umask**；**檔案 full = 666**、**目錄 full = 777**
B> 022 → 檔案 rw-r--r--、目錄 rwxr-xr-x
B> 033 → 檔案 rw-r--r--、目錄 rwxr--r--
B> 066 → 檔案 rw-------、目錄 rwx--x--x
B> 277 → 檔案 r--------、目錄 r-x------
B> 反推：umask = 想移除的位元（目錄可直接 777 − 目標）
?sa A. 若希望建立的目錄其屬性為 d --- r-- r-x，umask 需設定為何？ B. 若希望建立的檔案其屬性為 - r-- --- rw-，且目錄的 user/group/other 都具有 x 權限，umask 需設定為何？
S> 2023 期末 Q13
R> A. 目標目錄權限 --- r-- r-x = 045。目錄從 777 出發，需要遮掉的位元 = 777 − 045 = 732，所以 umask 732。
R> B. 目標檔案權限 r-- --- rw- = 406。檔案從 666 出發：user 要拿掉 w（2）、group 要拿掉 rw（6）、other 不拿（0），所以 umask 的 rw 部分為 260；又要求目錄的 u/g/o 都有 x，因此 umask 不能含任何 x（1）位元。umask = 260。驗證：檔案 666 & ~260 = 406（r-----rw-）；目錄 777 & ~260 = 517（r-x--xrwx），三者都有 x。
P> A. 732
P> B. 260
P> 說明以 666 / 777 為基準並遮罩
?fill umask 為 027 時，新建「檔案」的權限數字是＿＿
= 640
E> 666 & ~027 → rw- r-- --- = 640。
?fill umask 為 027 時，新建「目錄」的權限數字是＿＿
= 750
E> 777 & ~027 = 750。
?fill umask 為 033 時，新建檔案的權限數字是＿＿（注意不是減法）
= 644
E> 666 的 other=6（rw-）遮掉 3（-wx）只剩 r-- = 4，不是 6−3=3。

@CARD fs.journal | Journaling、CoW 與 Extended Attributes
A> Journaling 像「先記帳再搬貨」：當機後看帳本就知道哪些做完、哪些要回滾，不用盤點整個倉庫（fsck 很快）。CoW 像「改作業時不在原稿上塗改，而是寫在新紙上再換掉」，沒改的部分共用同一張紙 → 快照幾乎不花空間。
B> **Journaling**：先把操作寫入 journal，再非同步 commit；當機後：完整 commit → 略過；部分 → rollback 或 commit；未 commit → 忽略或 commit
B> 好處：縮短 **fsck** 時間、減少不一致；例：**ext3、ext4、xfs、btrfs**
B> **CoW (Copy on Write)**：複製但未修改的資料指向同一個實體位址
B> CoW 優點：省空間、**低成本 snapshot**；缺點：可能不一致（reference count）、檔案「實際」使用空間不直觀；例：ZFS deduplication
B> **Extended attributes**：key-value 的 metadata，存在 inode，不由檔案系統解讀（mime_type、checksum、security attributes）
?mc Journaling filesystem 的主要好處？
+ 當機後復原快且較一致
- 讓檔案永遠不會損壞
- 自動備份所有檔案
- 讓讀取速度加倍
E> 當機後只需檢查 journal，大幅縮短 fsck 時間並降低不一致。它是一致性的保證機制，不是備份。
?mt 配對：
> Journaling :: 先寫 log 再 commit，當機後依 log 修復
> Copy on Write :: 未修改的資料共用同一份實體區塊
> Extended attributes :: 存在 inode 的 key-value metadata
E> btrfs 同時是 CoW 也有 journal 特性（log tree）。

@CARD fs.p_acl | 實作：ACL：權限位元不夠用的時候
A> 傳統權限只有「擁有者、一個群組、其他人」三格，現實需求常常塞不下：例如「這個人只能讀、那群人可以寫、其他人什麼都不行」。ACL 是在三格之外「額外貼的個人通行證」。ls -l 權限尾巴出現 + 號，就代表這個檔案有 ACL。

B> **-R** 遞迴套用到既有的檔案；預設 ACL 只影響之後新建的
B> 有預設 ACL 的目錄裡，新檔權限由預設 ACL 決定，不再套用一般的 umask
X> setfacl -m u:anonymous:rx /mnt/hw2/sftp/public
X> setfacl -d -m u:anonymous:rx /mnt/hw2/sftp/public
X> getfacl /mnt/hw2/sftp/public

- 會取代 dir 原本的擁有群組，之後 ls -l 顯示的群組變成 team

@CARD fs.p_chmodlab | 實作：特殊位元組合的設定與檢查
A> setgid、sticky 這些位元平常看不到，一組合起來就決定了共享目錄的規則。用八進位要多寫第四位數：4 = setuid、2 = setgid、1 = sticky，加起來放在最前面。
B> 八進位：**chmod 3775 dir** = setgid（2）+ sticky（1）+ rwxrwxr-x；**chmod 1777 /tmp** 就是 sticky
B> 符號寫法：**chmod g+s dir**（setgid）、**chmod +t dir**（sticky）、**chmod o-rwx 檔案**
B> ls -l 的顯示：執行位置出現 **s / t** 代表該位元與 x 都有；大寫 **S / T** 代表有特殊位元但**沒有 x**（通常是設錯了）
B> setgid 目錄：裡面新建的檔案與子目錄自動屬於該目錄的群組，子目錄也會繼承 setgid
B> 改目錄樹的擁有者：`chown -R sysadm:sftpusers public`；只改目錄不動檔案：`find public -type d -exec chmod 2775 {} +`
?fill 讓目錄同時擁有 setgid 與 sticky，且權限為 rwxrwxr-x，八進位寫成 chmod ＿＿ dir
