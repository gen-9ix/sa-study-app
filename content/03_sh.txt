@CARD sh.why | 為什麼寫 Shell Script
A> Shell script 是「膠水」：真正的重活交給現成工具（grep、awk、curl…），script 負責把它們黏在一起、照順序跑、看結果做決定。
B> 自動化重複的指令工作，不用寫完整應用程式
B> 用 pipe、redirection、exit status 把現有工具黏起來
B> 適合系統管理、部署、監控、批次工作
B> shell 是**直譯器**：腳本被逐行讀入、當作指令執行
B> 原則：**大部分實際工作由現有指令完成**時，shell 最強
?tf Shell 是直譯器，腳本內容會被讀入並當作指令執行。
=T
E> 不需編譯，逐行解析執行。
?mc 下列哪種工作最「不」適合用 shell script 完成？
+ 需要複雜資料結構與大量數值運算的程式
- 每天把 log 壓縮並搬到備份目錄
- 依序呼叫幾個指令完成部署
- 檢查服務是否存活並回報
E> shell 擅長把現有指令黏起來；複雜邏輯改用 Python 等語言。

@CARD sh.shebang | Shebang 與執行方式
A> Shebang (#!) 是腳本第一行的「指定翻譯員」：kernel 看到 #!/bin/sh，就叫 /bin/sh 來念這份稿子。如果沒寫，就看「誰拿到稿子」，你用哪個 shell 去跑，它就用自己的口音念，可能念錯。
B> **#!/bin/sh**：第一行指定直譯器；系統腳本的可攜預設
B> **chmod +x hello.sh; ./hello.sh**：直接執行需要執行權限，kernel 依 shebang 啟動直譯器
B> **sh hello.sh**：明確指定直譯器，**不需要執行權限**，shebang 只是註解
B> **#!/usr/bin/env bash**：透過 PATH 找 bash（但 PATH 會影響到底跑哪個直譯器）
B> 重視可重現性時，用**絕對路徑**指定直譯器
B> 沒有 shebang 用 ./script 執行：execve 失敗（ENOEXEC），**呼叫它的 shell** 會自己接手用自己的語法執行 → 結果取決於你當下的 shell（bash、tcsh…）
?sa 請說明 hw1.sh 第一行的 #!/bin/sh 是什麼並解釋其功能；若腳本中沒有該行，程式還可以正常執行並得出相同結果嗎？
S> 2025 期末 Q7
R> #!/bin/sh 稱為 shebang。直接執行腳本（./hw1.sh）時，kernel 的 execve 會讀到檔案開頭的 #!，改用後面指定的直譯器 /bin/sh 來執行這個檔案（等同 /bin/sh ./hw1.sh），確保用 POSIX sh 的語法解譯。
R> 沒有這行時「不一定」得到相同結果：若用 sh hw1.sh 明確指定直譯器，結果相同（此時 shebang 本來就只是註解）。若用 ./hw1.sh，execve 會因不是可辨識的執行檔格式而失敗（ENOEXEC），由「目前呼叫它的 shell」自行接手執行，若當下是 bash 可能剛好能跑（但語法行為可能與 sh 不同），若是 tcsh 等語法不同的 shell 就會出錯；judge 透過 ssh 呼叫時使用的 shell 也不確定。所以應保留 shebang。
P> shebang 指定直譯器路徑，kernel 依此啟動 /bin/sh
P> sh hw1.sh 方式仍可執行
P> ./hw1.sh 時由當下 shell 接手，結果依 shell 而定（如 tcsh 會失敗）
?sa a. 什麼是 shebang？ b. 若沒有 shebang，是否就無法執行 shell script？（若是，請解釋原因；若否，請舉反例）
S> 2023 期中 Q9
R> a. shebang 是腳本第一行以 #! 開頭、後接直譯器絕對路徑的指示（例如 #!/bin/sh），讓 kernel 在直接執行該檔時知道要用哪個程式來解譯。
R> b. 否。反例：sh script.sh 直接把檔案交給 sh 解譯即可執行，不需 shebang（也不需執行權限）；或在 shell 中用 . script.sh / source 讀入；甚至 ./script.sh 時目前的 shell 也會接手執行。
P> a. #! + 直譯器路徑，指定解譯程式
P> b. 否，舉出 sh script.sh 等反例

+ sh a.sh
- ./a.sh
- exec ./a.sh
- a.sh（在 PATH 目錄中）
E> sh a.sh 只需要讀取權限，因為是 sh 去讀檔案內容；直接執行需要 x 權限。
?tf 用 #!/usr/bin/env bash 時，實際執行的 bash 由 PATH 決定。
=T
E> env 會在 PATH 中找 bash，所以 PATH 會影響結果。

@CARD sh.perm | Permission denied 與執行權限
A> 檔案像一道門，r 是能看、w 是能改、x 是「能當成程式啟動」。沒有 x 就像拿著劇本卻不能上台演，但你可以請別人（sh）念出來。
B> 直接執行（./a.sh）需要 **x 權限**
B> 解法：**chmod u+x a.sh**（或 chmod 700 / 755），或改用 **sh a.sh**
B> 若檔案系統以 **noexec** 掛載，即使有 x 也不能直接執行
?sa 為何執行 a.sh 會發生 Permission denied？如何解決，讓使用者可正常執行該 script？
QX> $ ls -l a.sh
QX> -rw------- 1 tsaimh users 21 Nov 27 14:40 a.sh
QX> $ ./a.sh
QX> ./a.sh: Permission denied
S> 2023 期中 Q5
R> 原因：a.sh 的權限是 rw-------，擁有者只有讀寫、沒有執行（x）權限，直接以 ./a.sh 執行時 kernel 檢查 x 位元失敗，所以 Permission denied。
R> 解法：chmod u+x a.sh（或 chmod 700 a.sh）加上執行權限後再 ./a.sh；或不改權限，用 sh a.sh 讓直譯器讀取執行（只需讀取權限）。另外確認檔案系統沒有以 noexec 掛載，且腳本有正確的 shebang。
P> 缺少 x（執行）權限
P> chmod u+x a.sh 或 sh a.sh
?cmd 只替檔案擁有者加上 deploy.sh 的執行權限：
= chmod u+x deploy.sh
= chmod u+x ./deploy.sh
E> u = user（擁有者），+x 加上執行權。

@CARD sh.var | 變數與參數展開（預設值）
A> ${var:-預設} 是「你沒填我就先借你用一下」（不寫回）；${var:=預設} 是「你沒填我就幫你填上」（寫回）；${var:?訊息} 是「你沒填我就罷工並報錯」；${var:+替代} 是「你有填我才換成替代品」。
B> name=value 當前 shell；export name=value 讓 child 繼承；讀取 "$name" 或 "${name}"
B> **${var:-default}**：var 未設或空 → 用 default，**不賦值**
B> **${var:=default}**：未設或空 → **賦值**再使用
B> **${var:?message}**：未設或空 → 印訊息到 stderr 並**中止**
B> **${var:+alternate}**：var **有值**時才用 alternate
X> config=${CONFIG_FILE:-/etc/myapp.conf}
X> : "${HOME:?HOME must be set}"
?mt 配對（當 var 未設定或為空時）：
> ${var:-x} :: 結果為 x，但不改 var
> ${var:=x} :: 把 x 指定給 var 再使用
> ${var:?msg} :: 印出 msg 並中止
> ${var:+x} :: 結果為空（因為 var 沒有值）
E> :+ 剛好相反，有值才替換。
?mc unset A; echo "${A:-hi}"; echo "${A}" 會輸出？
+ hi 和一行空白
- hi 和 hi
- 兩行空白
- 錯誤訊息
E> :- 不會把預設值寫回 A。

@CARD sh.strop | 參數展開：字串操作
A> # 從「頭」砍、% 從「尾」砍（鍵盤上 # 在 $ 左邊、% 在 $ 右邊）；一個符號砍最短、兩個符號砍最長（貪心）。
B> **${#var}**：字串長度
B> **${var#pattern}**：移除**最短**符合的**前綴**；**${var##pattern}**：移除**最長**前綴
B> **${var%pattern}**：移除**最短**後綴；**${var%%pattern}**：移除**最長**後綴
X> path=/var/log/system.log
X> base=${path##*/}   # system.log
X> stem=${base%.log}  # system
X> dir=${path%/*}     # /var/log
M> # 在 $ 左邊砍頭、% 在 $ 右邊砍尾；雙寫 = 貪心
?fill path=/var/log/system.log，${path##*/} 的結果是＿＿
= system.log
E> ##*/ 移除最長的「任意字元 + /」前綴，只剩檔名（等同 basename）。
?fill f=archive.tar.gz，${f%.*} 的結果是＿＿
= archive.tar
E> % 移除最短的「.任意字元」後綴，只拿掉 .gz；${f%%.*} 才會變成 archive。
?fill s=hello，${#s} 的結果是＿＿
= 5
E> ${#var} 是長度。

@CARD sh.pos | 位置參數與特殊參數
A> 把腳本想成一場比賽：$0 是比賽名稱（腳本名）、$1 $2 是選手、$# 是選手人數、$? 是上一場的比分、$$ 是自己的身分證號、$! 是最近一個「放到背景」的選手的號碼。
B> **$0** 腳本名稱；**$1, $2…** 位置參數（從 $1 開始）
B> **$#** 參數個數；**$?** 最近一個指令的 exit status
B> **$$** 目前 shell 的 PID；**$!** 最近背景 pipeline 的 PID
X> ./my_web_server &
X> echo $! > /var/run/my_server.pid
?mt 配對特殊參數：
> $# :: 位置參數個數
> $? :: 上一個指令的 exit status
> $$ :: 目前 shell 的 PID
> $! :: 最近背景 process 的 PID
> $0 :: 腳本名稱
E> 常考，務必背熟。
?fill 執行 ./arg.sh abc 時，$# 的值是＿＿
= 1
E> 只有一個參數 abc；$0 不算。

@CARD sh.atstar | "$@" vs "$*"
A> "$@" 是「每位客人各自一張椅子」，即使客人名字有空白也不會被拆開；"$*" 是「把所有客人塞進同一張長椅」，變成一個字串。
B> **"$@"**：每個參數保持獨立（保留原本的邊界）→ 轉傳參數用這個
B> **"$*"**：所有參數合成**一個**字串（以 IFS 第一個字元連接）
X> # 參數：one "two words" three
X> for x in "$@"; do printf '<%s>\n' "$x"; done
X> # <one> <two words> <three>
X> printf '<%s>\n' "$*"
X> # <one two words three>

+ 3 次
- 4 次
- 1 次
- 0 次
E> "$@" 保留邊界，"two words" 是一個參數。
?mc 同樣的參數，printf '<%s>\n' "$*" 會印出幾行？
+ 1 行
- 3 行
- 4 行
- 0 行
E> "$*" 合成一個字串。

@CARD sh.exit | Exit Status 是 Shell 的布林值
A> Shell 沒有 true/false 型別，if 看的是指令的「成績」：0 = 成功 = 真。
B> 每個指令都回傳整數 exit status；**0 成功**，非 0 失敗或其他狀況
B> $? 是最近一個指令的狀態
B> if、while、&&、|| 都是根據 exit status 做決定
X> grep -q '^root:' /etc/passwd
X> printf 'status = %s\n' "$?"
?tf 在 shell 中，if 判斷的是指令的 exit status，而不是布林型別的值。
=T
E> exit status 0 視為真。
?fill 取得「上一個指令」exit status 的特殊變數是＿＿
= $?
E> 0 代表成功，非 0 代表失敗。
?mc 執行 false && echo A || echo B 會印出什麼？
+ B
- A
- A 和 B
- 什麼都不印
E> false 的 exit status 非 0，&& 後面不執行；整體失敗所以執行 || 後面的 echo B。

@CARD sh.test | test 與 [ ]
A> [ 其實是一個「指令」（就是 test），所以它和參數之間一定要空白；結尾的 ] 是它要求的最後一個參數。把 [ 想成一個人名，你不會把名字和下一個字黏在一起。
B> **[ 是一個指令**，結尾 ] 是必要的參數
B> [ 、運算子、] 前後**都要有空白**
B> 測試裡的變數要加引號：[ "$mode" = production ] 在 $mode 為空時也安全
B> ⚠ test 裡的 > < 會被 shell 當成 **redirection**！
X> test -f /etc/passwd; echo $?
X> [ -f /etc/passwd ]; echo $?
?sa a. 下面這個指令會輸出什麼？ b. 若要把比較改成數值比較，應該怎麼改？改完後會輸出什麼？
QX> $ test 14 > 123 ; echo $?
S> 2023 期中 Q10
R> a. 輸出 0。因為 > 被 shell 當成 output redirection，實際執行的是 test 14（stdout 導向到名為 123 的檔案，並建立該檔案）。test 只有一個非空字串參數時為真，所以 exit status 為 0。
R> b. 改成 test 14 -gt 123 ; echo $?（或 [ 14 -gt 123 ]），數值比較 14 > 123 為假，輸出 1。
P> a. 輸出 0
P> a. > 是 redirection，建立檔案 123，test 14 為真
P> b. 用 -gt，輸出 1
?mc [ "$a"="$b" ] 這樣寫（等號兩旁沒空白）會怎樣？
+ 被當成單一非空字串，永遠為真
- 正確比較兩個字串是否相等
- 語法錯誤，test 會回報錯誤
- 永遠為假，因為沒有運算子
E> 沒空白就變成一個參數 "x=y"，test 單一非空字串為真。

@CARD sh.ftest | 檔案測試
A> 檢查檔案的「健康檢查表」：-e 存在嗎、-f 是一般檔嗎、-d 是目錄嗎、-L 是捷徑嗎、-r/-w/-x 能讀/寫/執行嗎、-s 有內容嗎。
B> **-e** 存在；**-f** 一般檔案；**-d** 目錄；**-L** symbolic link
B> **-r / -w / -x** 可讀 / 可寫 / 可執行
B> **-s** 存在且大小 > 0
B> **f1 -nt f2**：f1 比 f2 新
?mt 配對 file test：

> -f :: 是一般檔案
> -s :: 存在且大小大於 0

@CARD sh.stest | 字串與整數比較
A> 字串比較用符號（= !=），整數比較用「英文縮寫」（-eq -ne -gt -ge -lt -le）：equal、not equal、greater than、greater or equal、less than、less or equal。
B> 字串：**-z** 長度為 0、**-n** 長度非 0、**=** 相等、**!=** 不等
B> POSIX sh 用 **=** 不用 ==；[ ] 中避免用 < > 做字串排序
B> 整數：**-eq -ne -gt -ge -lt -le**
B> 組合條件用 shell 的 **&& ||**，不要用 [ ] 裡的 -a -o（歷史上有歧義）
X> if [ "$count" -gt 10 ]; then printf 'large\n'; fi
X> if [ -r "$file" ] && [ -s "$file" ]; then process "$file"; fi
?mt 配對整數比較：
> -eq :: 等於
> -ne :: 不等於
> -gt :: 大於
> -le :: 小於或等於
E> 字串用 = 和 !=。
?fill 判斷字串 $s 長度為 0：[ ＿＿ "$s" ]
= -z
E> -z zero length；-n non-zero。
?tf 在 POSIX sh 的 [ ] 中，建議用 == 比較字串。
=F
E> POSIX 是 =；== 是 bash 擴充。

@CARD sh.for | for 迴圈
A> for 是「點名」：把清單上的名字一個一個叫出來。用 *.log 讓 shell 幫你點檔名是安全的；用 $(ls) 會把含空白的檔名拆成兩個人。
B> 明確值：for x in red green blue; do …; done
B> 安全處理檔案：for f in *.log; do …; done（處理沒有符合時的情況）
B> **避免 for f in $(ls)**：檔名有空白、tab、換行、glob 字元時會壞掉
B> 使用時記得 "$x" 加引號
?sa 下面 shell script 的執行結果為何？
QX> #!/bin/sh
QX> for i in `seq 1 5`; do
QX>     echo "Homework $i is easy!"
QX> done
S> 2023 期中 Q12

R> Homework 2 is easy!
R> Homework 3 is easy!
R> Homework 4 is easy!

- $(ls) 的輸出包含顏色控制碼，檔名會比對失敗
E> 用 for f in * 或 for f in *.log。

@CARD sh.while | while 與 read
A> while read 是「一行一行讀信」。IFS= 是「不要幫我修剪頭尾空白」，-r 是「反斜線照抄不要當跳脫」。重點陷阱：cat file | while … 的 while 跑在 subshell（另一個房間），在裡面數的數字，出了房間就消失。
B> **while IFS= read -r line; do …; done < input.txt**
B> **IFS=** 保留行首行尾空白；**read -r** 不解讀反斜線
B> 需要迴圈後的變數值時，用 **redirect（< file）** 而不是 pipe 進 while
B> pipe 進 while 會在 subshell 執行，變數改變不會傳回
X> count=0
X> cat data.txt | while read -r line; do count=$((count+1)); done
X> echo "Total lines: $count"   # 常常是 0！
?mc 上面範例的 count 最後為什麼是 0？

@CARD sh.p_printf | 實作：printf 排出整齊的欄位

B> 參數比格式多時，格式會**重複套用**：`printf '%s\n' a b c` 印三行
B> 時間格式：`date +'%F %T'` 得到 2025-10-02 20:57:50；`date -d @1759409870 +'%F %T'` 把 epoch 秒數轉成可讀時間；`date -d '2025-10-02 20:57:50' +%s` 反過來
B> 已經有空白分隔的輸出想對齊：接 **column -t**
B> 檢查輸出有沒有偷藏 TAB：`cmd | cat -A`，TAB 會顯示成 **^I**、行尾顯示 **$**
X> printf '%-6s%-10s%s\n' ID SUBVOLUME TIME
X> printf '%-6s%-10s%s\n' "$id" "$sub" "$time"
X> SnApper list | cat -A | head -n 3
?cmd 用 printf 印出「ID」靠左佔 6 格、接著「NAME」，最後換行：
= printf '%-6s%s\n' ID NAME
= printf "%-6s%s\n" ID NAME
= printf '%-6sNAME\n' ID
E> - 表示靠左，6 是最小寬度。
?mc 懷疑腳本輸出的欄位是用 TAB 分隔的，怎麼確認？
+ 把輸出接到 cat -A，TAB 會顯示成 ^I
- 把輸出接到 od -c | head -1，看看第一個字元
- 用 sort 看看欄位的排序順序
- 用 echo $? 看指令的回傳值
E> cat -A 會把不可見字元顯示出來，行尾的 $ 也能抓出多餘空白。

@CARD sh.p_parse | 實作：解析其他指令的輸出
A> 寫管理腳本有一半時間在「讀別的指令吐出來的表格」。兩個主力：awk 負責挑欄位與篩選，while read 負責一行一行拿進 shell 變數處理。最大的坑是「pipe 右邊的 while 跑在 subshell，裡面改的變數出來就不見了」。
B> awk：**$1、$2** 第幾欄、**$NF** 最後一欄、**NR>1** 跳過表頭、**-v n="$x"** 把 shell 變數傳進去、**-F:** 指定分隔字元
B> 逐行讀：`while read -r id path; do ...; done`；**-r** 避免反斜線被吃掉，最後一個變數會拿到剩下的整段
B> `cmd | while read ...; do count=$((count+1)); done` 迴圈結束後 count 還是原值（subshell）；改用 **done < <(cmd)** 就不會
B> 取最小 / 最大：`sort -n | head -n 1`、`sort -n | tail -n 1`；計數：`wc -l` 或 `grep -c`
B> 字串切割不必開新 process：`${path##*/}` 取最後一段、`${path%/*}` 去掉最後一段
X> btrfs subvolume list /mnt/root5 | awk '$NF ~ /^snapshot\/pool1\// {print $2, $NF}'
X> while read -r id path; do
X>   echo "id=$id name=${path##*/}"
X> done < <(btrfs subvolume list /mnt/root5 | awk '{print $2, $NF}')
?mc 下列程式執行後 n 的值是？

QX> echo $n

- 2
- 1
- 空字串
E> 0，因為 pipe 右邊的 while 在 subshell 中執行。改成 `done < <(printf 'a\nb\n')` 就會得到 2。
?cmd 用 awk 印出 /etc/passwd 每一行的第 1 欄與最後一欄（分隔字元是冒號）：
= awk -F: '{print $1, $NF}' /etc/passwd
= awk -F: '{print $1,$NF}' /etc/passwd
= awk -F ':' '{print $1, $NF}' /etc/passwd
E> $NF 是最後一欄，NF 本身是欄位數。
?fill path=snapshot/pool1/@20251003-163650 時，要只取出最後一段 @20251003-163650，可以寫 ${path＿＿}

@CARD sh.p_install | 實作：把腳本裝成系統指令
A> 寫完的腳本要「上架」才算數：放進 PATH 上的目錄、有執行權限、第一行 shebang 正確、而且要被指定的使用者讀得到。HW2 的 judge 會用 `$(which SnApper)` 去拿你的腳本，任何一項沒做就是 0 分。
B> 慣例位置 **/usr/local/bin**；一步到位：`install -m 755 SnApper /usr/local/bin/SnApper`（複製 + 設權限）
B> 第一行 **#!/bin/bash**（用了 bash 語法就不要寫 #!/bin/sh，Debian 的 sh 是 dash）
B> 在 Windows 編輯過的檔會有 CRLF，錯誤長這樣：**bad interpreter: /bin/bash^M**；用 `sed -i 's/\r$//' 檔案` 或 dos2unix 修
B> 給別人（或 judge）讀取：權限至少 **755**，而且路徑上每層目錄都要可進入
B> 驗證：`which SnApper`、`ls -l "$(which SnApper)"`、`sudo -u judge cat "$(which SnApper)" | head -n 1`
?cmd 把目前目錄的 SnApper 複製到 /usr/local/bin/SnApper，並同時把權限設成 755：
= install -m 755 SnApper /usr/local/bin/SnApper
= install -m 755 SnApper /usr/local/bin/
= install -m 755 SnApper /usr/local/bin
= install -m 0755 SnApper /usr/local/bin/SnApper
E> 等同 cp 之後再 chmod 755。
?mc 執行腳本時出現 `/bin/bash^M: bad interpreter`，原因是？

- PATH 沒有 /bin

@CARD sh.p_bytes | 實作：檔案簽章與雜湊比對
A> 副檔名可以亂改，但檔案開頭的幾個 bytes（magic number）騙不了人：ELF 執行檔一定以 7f 45 4c 46 開頭。雜湊（MD5）則像檔案的指紋，內容一樣指紋就一樣。sftp_watchd 就是靠這兩招抓違規檔。
B> 取前 4 bytes 轉十六進位：`head -c 4 檔案 | xxd -p` 得到 **7f454c46**；沒有 xxd 時用 `od -An -tx1 -N4`
B> **file 檔案**：直接告訴你類型（ELF 64-bit ...、ASCII text ...），人工確認很方便
B> MD5：`md5sum 檔案` 輸出「雜湊 兩個空白 檔名」，只取雜湊：`md5sum "$f" | awk '{print $1}'` 或 `cut -d' ' -f1`
B> 黑名單比對：存成陣列或檔案，用 **case** 或 **grep -qxF** 判斷
B> 檔案擁有者（誰上傳的）：`stat -c %U 檔案`；其他常用：**%a** 八進位權限、**%s** 大小、**%Y** 修改時間 epoch
X> sig=$(head -c 4 "$f" | xxd -p)
X> [ "$sig" = 7f454c46 ] && echo "ELF"
X> sum=$(md5sum "$f" | awk '{print $1}')
X> owner=$(stat -c %U "$f")
?cmd 印出 /bin/ls 的前 4 個 bytes 的十六進位（連續不分隔）：
= head -c 4 /bin/ls | xxd -p
= xxd -p -l 4 /bin/ls
= xxd -l 4 -p /bin/ls
E> 結果是 7f454c46，也就是 \x7f E L F。
?cmd 用 stat 只印出 upload.bin 的擁有者名稱：
= stat -c %U upload.bin
= stat -c '%U' upload.bin
= stat --format=%U upload.bin
E> %U 是擁有者名稱、%u 是 UID。
?mc `md5sum a.txt` 的輸出是 `d41d8cd9... a.txt`。腳本只需要雜湊值本身，應該？
+ 接上 awk '{print $1}' 取第一欄
- md5sum 加上 -q 選項，只輸出雜湊值
- 用 tail -c 32 取最後 32 個字元
- 用 basename 去掉後面的檔名
E> GNU md5sum 沒有 -q（那是 BSD md5 的選項）；輸出格式是「雜湊、空白、檔名」。

@CARD sh.p_inotify | 實作：inotifywait 事件迴圈
A> 要「一有新檔就處理」，笨方法是每秒 ls 一次；聰明方法是請 kernel 通知你。inotifywait -m 像「守在門口的感應器」，每發生一個事件就吐一行字，你用 while read 接起來處理，這就是一個 daemon 的主迴圈。
B> 安裝：`apt install inotify-tools`；**-m** 持續監看（不加就只等一次事件就結束）、**-r** 遞迴子目錄、**-e 事件** 可重複指定
B> 要等 **close_write**（寫完並關檔）再檢查；用 create 會在檔案還是空的 / 寫到一半時就觸發
B> 再加 **moved_to** 接住「先寫暫存檔再改名」的上傳方式
B> `--format '%w%f'` 只輸出完整路徑（%w 目錄、%f 檔名、%e 事件）
B> 搬檔時用 `mv -- "$f" "$dest/"`：**--** 之後的東西不會被當成選項，檔名以 - 開頭也安全
B> 記得排除自己的輸出目錄（例如 .violated），不然搬進去又觸發一次
X> inotifywait -m -r -e close_write -e moved_to --format '%w%f' "$dir" |
X> while read -r f; do
X>   [ -f "$f" ] || continue
X>   check_file "$f"
X> done
?mc 監看上傳檔案時，為什麼用 close_write 事件而不是 create？
+ create 時內容還沒寫完
- create 事件不支援遞迴監看
- close_write 的效能比較好
- create 只會對目錄觸發
E> create 發生時檔案才剛建立、內容還沒寫完；close_write 才表示寫入完成。太早檢查會讀到空檔或半個檔，簽章與雜湊都會判斷錯。
?fill inotifywait 要持續監看、處理完一個事件後不結束，需要的選項是 ＿
= -m

?mc 腳本中寫 `mv -- "$f" "$dest/"`，其中 `--` 的作用是？
+ 選項到此為止
- 強制覆蓋目的檔
- 保留檔案的權限與時間
- 讓 mv 遞迴搬移
E> 表示選項到此為止，後面即使以 - 開頭也當成檔名。使用者可以上傳名叫 -rf 的檔案，沒有 -- 就會被當成選項。

@CARD sh.p_safety | 實作：腳本最常見的地雷
A> 腳本的事故大多不是邏輯錯，而是「變數是空的」和「沒加引號」。想像 rm -rf "$dir"/ 裡的 dir 剛好是空字串，那一行就變成 rm -rf /。
B> 變數一律加雙引號 **"$var"**：檔名有空白、變數為空時才不會被拆開或消失
B> 關鍵變數用 **${var:?訊息}**：是空的就直接報錯中止，不會繼續往下跑
B> `cd "$dir" || exit 1`：cd 失敗就停，不然後面的指令會在錯的目錄執行
B> **[ -z "$x" ]** 空字串、**[ -n "$x" ]** 非空；比較數字用 -eq / -lt，別用 = 或 <
B> 使用者輸入當參數前先驗證：`case "$id" in ''|*[!0-9]*) echo "bad id" >&2; exit 1 ;; esac`
B> **set -u** 讓未定義變數直接報錯；**set -e** 遇錯即停，但在 if 條件、&& / || 之中的失敗不會觸發，別過度依賴
X> rm -rf "${target:?target is empty}"/
X> cd "$workdir" || exit 1
X> case "$id" in ''|*[!0-9]*) echo "ID must be a number" >&2; exit 1 ;; esac
?mc `rm -rf "${dir:?}"/tmp` 中的 `${dir:?}` 作用是？
+ dir 未設定或為空時，印出錯誤並中止，不會執行 rm
- dir 未設定時，先提示使用者輸入一個值，再繼續執行 rm
- dir 為空時，自動改用 /tmp 當作預設值
- 把 dir 轉換成以 / 開頭的絕對路徑
E> 這是防止「空變數 + rm -rf」災難的標準寫法。
?mc 檢查變數 id 是否「只由數字組成」，下列哪個 case pattern 會抓到不合法的值？
+ ''|*[!0-9]*
- [0-9]
- *[0-9]*
- *[0-9]*|[0-9]
E> 空字串，或含有任何一個「非數字」字元，都算不合法。
?tf 寫了 set -e 之後，腳本中任何一個指令失敗，腳本一定會立刻結束。
=F
E> if / while 的條件、以及 && 與 || 左邊的指令失敗不會觸發 set -e。
